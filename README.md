## 0. 先看这张表：功能要不要增、要不要减

你的六项需求我一项没删，全部保留；但把其中两项**拆成两期**，另外**补了 9 项**不改就做不稳的功能。

| 功能 | 来源 | 建议 | 理由（基于接口文档 / 开发成本） |
| --- | --- | --- | --- |
| 连接蓝牙卡尺 | 原话 | **V1 必做** | BLE 服务、特征、广播名前缀在接口文档里已写死，可直接落地 |
| 实时读数 + 记录数据 | 原话 | **V1 必做** | 核心闭环起点 |
| 记录后形成表格 | 原话 | **V1 必做** | 核心闭环 |
| 上传特定表格作为模板 | 原话 | **拆期：V1 只做「内置模板 + CSV 模板导入」；自定义 xlsx 模板（合并单元格、样式、公式、表头映射）放 V2** | 这是 V1 最大的工作量与不确定性来源。xlsx 解析 + 样式还原 + 字段映射做全，V1 会失控；先验证「模板→表格→导出」这条链跑得通 |
| 数据分析成柱状图 / 线状图 | 原话 | **V1 必做** | 折线图（按序号看趋势）+ 柱状图（按批次对比），带公差参考线 |

| 连续上报去重 / 去抖 | 【AI建议·增】 | **V1 必做** | `DAT1` 是连续上报，同一个读数会反复刷屏，不去重表格几秒就几百行 |

| 断连保护 / 未落库提示 | 【AI建议·增】 | **V1 必做** | 文档原话：**「卡尺不保留历史测量数据，不能对历史数据进行查询」**。数据只在 App 里，断连丢一次就永久没了。必须收到即落库 + 断线红条提示 + 自动重连 |
| 公差上下限 + 合格判定 | 【AI建议·增】 | **V1 做简易版**（填上下限，表格标红/标绿） | 测量数据不判合格，表格和图表价值减半；SPC、CPK、控制图延到 V3 |
| 按批次 / 工件分组 | 【AI建议·增】 | **V1 做简易批次** | 一次检验任务的数据要能归堆、能筛选、能单独出图 |
| 原始数据 CSV 导出 | 【AI建议·增】 | **V1 必做** | 见上「导出图表」一行 |
| 云同步 / 账号 / 多人协作 | 【AI建议·增，可不要】 | **延后 V3** | V1 纯本地、无后端、无登录，体积和审核风险都最低 |
| SPC / CPK / 控制图 / 直方图 / 散点图 | 【AI建议·增，可不要】 | **延后 V3** | 先验证「连得上、记得住、画得出、导得走」，再上统计深度 |
| 超差推送提醒 | 【AI建议·增，可不要】 | **延后 V2** | 要通知权限，V1 不碰 |

### 理解卡（v0.1 建立，v0.3 更新）

- 目标用户：车间检验员、计量/品质人员、需要把卡尺读数整理成检验记录的工程师。
- 核心问题：卡尺自己不存数据、也不出报表，靠手抄到 Excel 又慢又容易错。
- 首阶段目标：手机连上卡尺 → 按一下收一个读数 → 自动进表格 → 出图 → 图和表都能存到手机。
- 主流程：激活卡尺广播 → App 扫描 `GL-BLE#` 设备 → 连接并订阅 notify → 读数落库 → 表格查看 → 图表分析 → 导出 PNG/CSV。
- 已知约束：卡尺无历史数据可回读；V1 只做 Android；模板暂用公开类似项目格式，真实样表留待 V2 映射。
- 高风险面：蓝牙断连丢数、连续模式刷屏、双单位混存、xlsx 模板解析（已延 V2）。
- 影响架构的未知（**已关闭**）：目标平台 = Android APK；模板格式 = `gl_caliper_default.csv`；公差规则由模板列或设置页提供。

## ① 项目概述

一款手机 App，通过低功耗蓝牙连接广陆蓝牙数显卡尺，把每一次测量读数实时收下来存成本地表格，按上传的表格模板组织数据，生成柱状图 / 折线图等分析图，并把图表和原始数据导出到手机本地。解决的问题是：卡尺不存历史数据、人工抄录容易错、出报表要回电脑重做一遍。

## ② 用户画像

| 项 | 内容 |
| --- | --- |
| 目标用户 | 【AI建议】车间检验员、IQC/IPQC、计量室人员、现场工程师 |
| 使用场景 | 【AI建议】产线抽检、来料检验、首件确认；一手拿卡尺、一手拿手机，测完当场看趋势、当场出记录 |
| 痛点 | 卡尺只读当前值、不存历史；手写记录易抄错；回工位再录 Excel 费时；超差靠人眼判断 |
| 用户原话里的诉求 | 连蓝牙卡尺、记录成表格、上传模板、出柱状图/线状图、导出图表到本地 |

## ④ 页面文字原型

> 按钮点击后的去向逐条写明；【AI建议】表示这个页面或组件是我补的。

**P1 设备连接页**（V1）
- 标题：`连接卡尺`
- 组件：顶部状态条「未连接 / 扫描中 / 已连接：GL-BLE#xxxx」；设备列表（广播名 + MAC + 信号强度）；提示文字「长按卡尺红色 data 键 3 秒，屏幕闪 OK 后开始扫描」【AI建议，来自接口文档】
- 按钮：`扫描设备` → 刷新列表；点某一台 → 发起连接、订阅 notify → **成功后跳 P2 采集页**；`断开` → 回未连接态并弹「断连期间的数据不会补录」提示【AI建议】

**P2 采集页**（V1，核心页）
- 标题：`实时测量`
- 组件：超大当前读数（如 `+155.15 mm`）；单位切换 `mm / inch`；批次选择 `当前批次：默认批次 ▾`；本次已记条数；连接状态条；模式指示 `手动 / 连续`
- 按钮：`记录一条` → 手动模式下把当前读数写入表格，表格数字 +1，停留本页；`发一次采集 MEAS`【AI建议】→ 向卡尺发指令，等待 `DAT0` 回来；`清零 CLR`【AI建议】→ 发清零指令，提示「已清零」；`切换手动/连续`【AI建议】→ 发 `MOD:0`/`MOD:1`，连续模式下自动按去重规则入库；`查看表格` → **跳 P3**；`查看图表` → **跳 P5**；`设置` → **跳 P7**
- 断连时【AI建议】：整页顶部红条「蓝牙已断开，正在重连；卡尺不保存历史数据」，按钮置灰

**P3 数据表格页**（V1）
- 标题：`测量记录`
- 组件：批次下拉筛选；表格列（序号 / 时间 / 数值 / 单位 / 判定 / 备注 / 来源）；超差行标红、合格行标绿【AI建议】；顶部统计条 `n / 均值 / 最大 / 最小 / 合格率`
- 按钮：点某行 → 弹「编辑备注 / 删除该条」；`切换图表视图` → **跳 P5**；`导出` → **跳 P6**；`模板` → **跳 P4**

**P4 模板页**（V1 简版）
- 标题：`表格模板`
- 组件：模板列表（内置默认模板、已导入模板）；字段预览（列名、类型、是否必填）；提示「V1 支持 CSV 表头模板；xlsx 自定义模板在 V2」【AI建议】
- 按钮：`上传模板` → 打开系统文件选择 → 解析表头 → 显示字段映射预览；`设为当前模板` → 返回 P3，表格按新列展示；`删除模板` → 二次确认后移除

**P5 图表分析页**（V1）
- 标题：`数据分析`
- 组件：图表类型切换 `折线图 / 柱状图`；筛选（批次、时间范围）；公差上下限参考线（虚线）【AI建议】；统计卡片（均值、极差、标准差、合格率）【AI建议】
- 按钮：`导出这张图` → **跳 P6 并带上当前图表**；`返回表格` → **跳 P3**；点折线某个点 → 显示该条记录的数值与时间

**P6 导出页**（V1）
- 标题：`导出到本地`
- 组件：内容勾选 `图表 PNG` / `数据 CSV`（**默认两项都勾**，只导图片会把数据锁死在 App 里）；文件名预览（`批次名_20261112_1430.png`）；保存位置说明（手机「下载/Documents」或系统文件选择器 SAF）【AI建议】
- 按钮：`保存` → 写入手机本地并弹「已保存到 …」；`分享`【AI建议】→ 调系统分享面板；`完成` → 返回 P5

**P7 设置页**【AI建议·整页新增】（V1）
- 标题：`设置`
- 组件：默认单位、小数位数、公差上限/下限、连续模式去抖阈值（如 0.3 秒）、设备广播名前缀（默认 `GL-BLE#`）
- 按钮：`保存` → 写本地配置并返回来源页；`恢复默认` → 二次确认后重置

## ⑧ 技术选型方案（路线 C 已定稿）

> 2026-11-12 你已确认选 **C**。A / B 路线作废，`flutter_blue_plus` 及其商业授权问题不再列为待办。

| 层 | 定稿选型 | 理由 |
| --- | --- | --- |
| 目标平台 | **仅 Android，交付签名 APK** | V1 不打包 iOS IPA，不做 TestFlight / 开发者证书流程 |
| 语言 / UI | **Kotlin + 原生 View 或 Compose（M0 后定）** | 机型兼容最稳；与 openScale 同栈，借鉴成本最低 |
| 蓝牙层 | `blessed-android`(MIT) + `Android-Scanner-Compat-Library`(BSD-3) | 免费、机型 workaround 成熟、命令队列与自动重连 |
| 协议层 | **自己写** `GuangluCaliperHandler` | GitHub 代码检索 `GL-BLE#` 0 命中、`DAT0:m` 无相关命中，无现成实现可抄；按第 ⑨ 节逐条实现 |
| 本地存储 | **Room** + 显式 Migration | 读数「收到即落库」；**禁止 `fallbackToDestructiveMigration()`** |
| 数据存储原则 | 统一以 **整数微米 `value_um`** 存储，保留原始帧 | 协议同时支持 mm / inch；避免公差边界的浮点误差 |
| 图表 | **首选 Vico**(Apache-2.0)，MPAndroidChart 为回退备选 | 原 MPAndroidChart 生态已进入 maintenance mode；Vico 活跃维护。Vico 的 PNG 导出能力列入 M0 验证 |
| CSV | `kotlincsv` 或等价实现，UTF-8 BOM 导出 | V1 导入导出闭环；格式见 `V1开发基线.md` 第 4 节 |
| 版本基线 | **minSdk 26 / targetSdk 36 / compileSdk 36** | 约 99% 设备覆盖；数据与理由见 `V1开发基线.md` 第 2 节 |
| 后端 / 账号 / 云 | **不做** | V1 纯本地，**卸载 App 即丢数据**，所以 CSV 导出是必做项不是附加项 |

**取舍说明（不藏坑）**
- 既然只做 Android，跨端收益用不上；免费且机型兼容成熟的 BLE 库（MIT / BSD / Apache）都在原生侧。
- minSdk 26 覆盖约 99% 设备。数据源只统计 7 天内连过 Google Play 的设备，**中国大陆车间手机不在样本内、实际偏老**，因此不抬到 28（97%）或 29（93.9%），留安全垫。
- 纯 Java/Kotlin 依赖无 `.so`：**不做 ABI 分包、不受 Android 15+ 16KB 页对齐约束**（更正 v0.2「分 ABI 包体」）；但 **APK 签名必须 v1+v2+v3 全开**，否则部分老机型装不上。
- V1 连续模式按「前台采集」设计，后台保活不承诺；采集页需屏幕常亮，断连期间数据无法补录。
- 源码按 openScale 的分层组织（设备驱动抽象 / 用例层 / Room 数据层 / UI 分离），**只借鉴架构，不复制 GPL-3.0 源码**；目录结构与 7 条分层约束见 `V1开发基线.md` 第 3 节。

## ⑨ 蓝牙协议落地要点（来自接口文档，开发前逐条照做）

| 项 | 文档内容 |
| --- | --- |
| 协议 | 低功耗蓝牙（BLE） |
| 激活 | 长按卡尺红色 data 键 3 秒，液晶闪 `ok` 即激活广播 |
| 广播名 | 以 `GL-BLE#` 开头；`NAM:<string>` 可改名（1~16 字符，必须保留前缀），`NAM` 可查询 |
| Android / PC | Service `0000ffb0-0000-1000-8000-00805f9b34fb`，Characteristic `0000ffb2-0000-1000-8000-00805f9b34fb` |
| iOS | Service `0xFFB0`，Characteristic `0xFFB2`（短 UUID，代码里还原为 128 位）— **V1 不使用，仅存档** |
| 数据通道 | 连接成功后在上述特征上建立 **notify 监听**；每帧**自带设备 MAC 地址** |
| 手动上报 | `DAT0:<unit><sign><val>`（模块→APP），**APP 必须回复 `DAT0:OK`**；`unit`: `m`=mm / `i`=inch；`sign`: `+`/`-`；例 `DAT0:m+155.15`、`DAT0:i-1.2485` |
| 连续上报 | `DAT1:<unit><sign><val>`（模块→APP），**无需响应**；例 `DAT1:m+155.15` |
| 指令 | `MEAS` 启动一次采集（`MEAS:OK` / `MEAS:ERR` 设备忙）、`CLR` 清零（`CLR:OK`）、`MOD:0` 手动（默认）/ `MOD:1` 连续（`MOD:OK` / `MOD:ERR`） |
| **关键约束** | **「卡尺不保留历史测量数据，不能对历史数据进行查询」** → App 必须在 notify 回调里立即落库；断连期间的数据无法补录，也没有「同步历史」功能可做 |

**实现约束补充（本轮新增 12 项，均为 V1 必做，不新增功能编号）**：采集页屏幕常亮、notify 帧缓冲拼包且 `DAT0:OK` 只在完整帧解析成功后回、`DAT1` 去重量化为「值变化 ≤ 0.01mm 且间隔 ≤ 300ms」、双时间戳、多台 `GL-BLE#` 按上次 MAC 自动重连、诊断日志导出、签名 v1+v2+v3、Room 显式 Migration、权限引导页、导出默认同时勾 CSV、`MEAS:ERR`/`MOD:ERR` 重试、UTF-8 BOM。逐条理由与落点见 [V1开发基线.md](./V1开发基线.md) 第 5 节；第 ⑤ 节的 18 项功能清单编号不变。

## ⑩ 数据模型（V1，Room / SQLite）

| 表 | 主要字段 | 说明 |
| --- | --- | --- |
| `device` | `mac`, `name`, `last_connected_at`, **`is_last_used`** | 文档说数据帧带 MAC；`is_last_used` 支撑多卡尺自动重连 |
| `batch` | `id`, `name`, `template_id`, `unit`, **`nominal_um`**, **`lower_limit_um`**, **`upper_limit_um`**, `created_at` | 一次检验任务；公差同为整数微米 |
| `measurement` | `id`, `batch_id`, `seq`, `device_mac`, **`value_um`**, `raw_value`, `raw_unit`, `sign`, `captured_at`, **`elapsed_realtime`**, `verdict`, `note`, `source` | **`value_mm` → `value_um`**（0.001mm 整数 Long），避免公差边界浮点误差；`raw_*` 保留原始帧；`source` = `DAT0`/`DAT1`/`MANUAL`/`IMPORT`；`verdict` = 合格/超差/未判定 |
| `template` | `id`, `name`, `type`, `columns_json`, `created_at` | `type` = `builtin` / `csv`（`xlsx` 留枚举，V1 不实现） |
| `app_meta` | `schema_version`, `app_version` | 支撑显式迁移与升级前备份提示 |

> 换算只有一处：`i` → `mm` 乘 25.4，再 ×1000 取整为微米；`sign` 单独保留用于追溯。字段定义与 CSV 列映射见 [V1开发基线.md](./V1开发基线.md) 第 4、6 节。

### 17.1 协议核查证据（本轮实读 .doc 正文）

本地《广陆蓝牙设备数字化接口_通用.doc》正文只定义六类指令：`DAT0` / `DAT1`（模块→APP 数据帧）、`DAT0:OK`（握手）、`NAM:<string>`（改广播名，回 `NAM:OK` / `NAM:ERR`，须保留 `GL-BLE#` 前缀）、`MEAS`、`CLR`、`MOD:0/1`。**没有**自动发射时长、休眠时间、结束符或任何 HID 配置指令。文档里超链接的《蓝牙卡尺说明书.pdf》本地不存在。

### 17.2 HID 硬边界（必须如实告知）

| 证据 | 内容 |
| --- | --- |
| Android `BluetoothHidDevice`（API 28+） | 让**手机当 HID 键盘**发给别的主机，方向与本项目相反；系统全局只允许注册一个 App、退到后台自动注销、且依赖厂商实现 |
| HID Host | 是系统服务 / 隐藏 API，第三方 App 拿不到 profile proxy；卡尺模拟键盘时字符由系统注入焦点控件，App 不能反向写卡尺参数 |
| 公开产品资料 | 广陆蓝牙卡尺 / USB 接收器支持「私有 BLE 软件连接模式」与「HID 键盘配对模式」两条独立链路；回车 / Tab 结尾是 HID 往 Excel 输数的概念 |

**结论**：在已确认的技术路线 C（纯原生 Kotlin + BLE Central + `blessed-android`）下，**App 无法配置卡尺的 HID 结束符、自动发射时长和休眠时间**。这三项由卡尺固件持有，需厂商配置指令集 / PC 配置工具 / 卡尺按键设置。V1 不做「假下发」，界面不得显示「已配置成功」。

| 项 | V1 做什么 | 明确不做什么 |
| --- | --- | --- |
| `NAM` 改名 | 选通道 → 输入 `GL-BLE#xxx`（≤16 字符、必须保留前缀）→ 写入 `0000ffb2` 特征 → 显示 `NAM:OK` / `NAM:ERR`，失败重试 | 不全局广播改名；7 路同时在线时只对选中通道生效 |
