## 5. 本轮发现并修复的问题

| # | 问题 | 修复 |
| --- | --- | --- |
| 1 | `BlessedTransport.isConnected()` 用 `peripherals.containsKey(mac)` 判断，而 `connect()` 在真正连上前就写入 map → 未连上却返回 true | 改为 `peripherals[mac]?.state == ConnectionState.CONNECTED`（已用 `javap` 核实 blessed-android 2.5.3 的 `getState()` API） |

## 7. 未整改项与风险（如实列出）

1. **存量命名前缀**：83 处 `private val/var` 用 camelCase、4 处布尔字段（`needsAck`、`legacyChannel`、`bomRemoved` ×2）未用 `is` 前缀。其中 `legacyChannel` 是 Room 实体列名、`needsAck` 是跨层 data class 字段，全量重命名会触及 DB schema 与 31 个文件、需单独一轮专项重构 + 全量回归。按规范第十六节第 5 条，**本轮新增代码已按规范写**（如 `mFlushSignal`），未向存量看齐；用户此前明确「框架已认可，不要重构、只增加功能」，故不做机械重命名。如团队要求 100% 对齐，需单独立项。
2. **Activity Result API**：`startActivityForResult` / `onActivityResult` / `requestPermissions` / `onRequestPermissionsResult` 共 6 条 deprecated 警告。迁移涉及 Activity 生命周期与 SAF 回调注册时机，本机无真机可验，留待 M0 实机阶段一并迁移，避免引入未验证回归。
3. **覆盖率与 UI 测试**：规范第九节要求覆盖率 ≥ 80% 且建立 Espresso；当前仅 39 项 JVM 单测覆盖协议 / 帧缓冲 / 换算 / 去重 / CSV / HID 纯逻辑，Android UI 与 BLE 层无法由 JVM 测试覆盖，覆盖率未统计、未达标。
4. **UI 构建方式**：纯代码 View 与规范第十四节建议的 XML / ConstraintLayout / Material 组件不一致，属基线 13 节有意为之（M0 前压缩编译面），如需对齐需重做布局层。
5. **签名档位**：debug 包仅 v2 = true（v1 / v3 / v3.1 / v4 = false）。minSdk 26 ≥ 24，可正常安装；基线 2.4 的 v1+v2+v3 针对 release 包，仍未验证。
6. **M0 实机验证全部阻塞（最高优先级）**：卡尺实物 + Android 真机 + BLE 抓包；7 路机型并发上限实测；`DAT0:OK` 回包时机与帧尾是否带 CR/LF/Tab；`NAM` 下发 / 查询格式；HID 键盘录入实链；release 签名。**APK 能安装 ≠ 蓝牙链路已验证**。

### 13.2 诊断结论（可复现的代码层证据）

| # | 缺陷 | 证据 | 修复 |
| --- | --- | --- | --- |
| 1 | 扫描结果静默丢弃 | `BlessedTransport.onDiscoveredPeripheral` 原为 `val name = peripheral.name ?: return` + `startsWith(namePrefix)` 后直接 return，**无任何日志**；Android 12+ `BluetoothDevice.getName()` 常为 null，广播名在 `ScanRecord.deviceName` | 新增纯函数 `pickBroadcastName(cached, advertised)` 回退，被过滤设备写 `SCAN_SKIP` 诊断日志 |

### 13.3 权限与 API 兼容核查

- `scanReadiness()` 在 API ≥31 先校验 `BLUETOOTH_SCAN` / `BLUETOOTH_CONNECT` 再访问 `BluetoothAdapter.isEnabled`，避免无权限访问蓝牙适配器；API ≤30 校验 `ACCESS_FINE_LOCATION` 并用 `LocationManagerCompat.isLocationEnabled()` 覆盖 minSdk 26（不直接调 API 28+ 的 `LocationManager.isLocationEnabled()`）。
- `DiagnosticsUseCase.log()` 为 `@Synchronized`，可安全承接 BLE 回调线程与定时器线程写入。
- Manifest 权限声明未改动；`aapt2 dump badging` 复核 `BLUETOOTH_ADVERTISE` 计数 0。
